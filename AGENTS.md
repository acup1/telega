# telega: рабочие требования

## Цель

TUI-клиент Telegram на `terminalib`, визуально и по управлению близкий к
официальному клиенту, но минималистичный и без сплошных цветных фонов.

## Обязательные инварианты

- `nix run .` собирает и запускает приложение.
- Esc/q выходят только из начальной папки All chats (ID 0), когда чат не открыт.
  Иначе закрывают текущее меню/профиль/чат либо возвращают в начальную папку.
  Текстовый ввод имеет приоритет; при выходе останавливаются плееры, удаляются
  TGP-изображения и восстанавливается терминал, даже при ошибке очистки графики.
- История сообщений имеет бесконечную постраничную догрузку. Догрузку запускают
  и колесо мыши, и достижение начала страницы клавишей `↑`.
- Latest имеет отдельную mouse-hitbox и возвращает к актуальному концу истории,
  в том числе после перехода к старому закрепу/ответу с неполным новым контекстом.
  Нажатие всегда запрашивает последние сообщения с сервера, независимо от
  has_newer_messages: локальный конец загруженного списка не считается Latest.
- В ленте `↑/↓` выбирают и прокручивают сообщения. Они не переключают медиа.
- В полноэкранной галерее только `←/→` переключают соседние изображения.
- Полноэкранная галерея закрывается `Esc` или левым кликом вне изображения.
- Одиночный Esc не должен ждать следующей клавиши, даже при бесконечном
  ожидании ввода; событие мыши сразу после Esc не поглощает закрытие viewer.
- Полноэкранное медиа всегда имеет верхний TGP `z-index` и перекрывает текст,
  аватары и другие TGP-картинки нижних слоёв.
- Галерея не ограничена уже загруженной лентой: на `←/→` соседнее медиа
  запрашивается напрямую из истории Telegram в обе стороны.
- Одиночные изображения сохраняют исходные пропорции. Альбомы используют
  Telegram-подобную сетку; плитки допускают центральное кадрирование, но не
  растяжение.
- Фото, web-preview и аватары рисуются через TGP. Стикеры (WEBP, TGS, WEBM)
  отображаются и анимируются непосредственно в сообщении, без подписи типа
  вложения и без перехода в галерею по клику или Enter.
- TGS учитывает in/out point и FPS, разбирается один раз на анимацию; первый
  PNG передаётся в ленту до завершения декодирования. Большие кадры ограничены
  256 px, WEBM сохраняет альфа-канал. Python с модулем lottie входит в Nix PATH.
- Над визуальными вложениями нет подписей image/album, значков типа медиа и
  текстовых заглушек загрузки. Без TGP по центру — Nerd Font glyph, а при
  отключённых Nerd Fonts — `!`. Подписи самого сообщения сохраняются.
- GIF (в том числе Telegram MP4 animation) автоматически и зацикленно играют
  в видимых сообщениях, без звука и полноэкранного просмотра; вне экрана
  декодер останавливается. Очередь — два кадра, RAM-кеш — 2 МиБ на GIF.
- Кружки запускаются по клику и играют внутри сообщения с круговой альфа-маской,
  паузой и перемоткой. Кружок, голосовое и музыка делят один звуковой канал.
  При запуске кружок увеличивается в пределах viewport; после конца/смены
  аудиосообщения возвращается к компактному размеру, не открывая полный экран.
- Окончание/сбой декодера не закрывает видео-вьювер: остаются кадр и контролы
  повтора/перемотки. Обложки исключаются из выбора видеодорожки; предусмотрен
  запасной программный режим декодирования, диагностика только в журнале.
- Видео, кружки и анимации декодируются `ffmpeg`, их кадры выводятся через TGP;
  звук видео, музыка и голосовые используют `mpv`, `ffplay` или `afplay`.
- В ленте фото и видео сначала используют миниатюры Telegram. Полный файл не
  скачивается до явного открытия медиа.
- Кадры видео действительно сменяются через TGP; для совместимости используется
  синхронизированный double-buffer, а не только замена animation frame.
- Комментарии каналов, их вложения и связанный чат доступны без вступления в
  связанную группу. Комментарии можно читать и отправлять из клиента.
- После запуска TUI никакие ошибки, panic-сообщения и вывод дочерних процессов
  не попадают в терминал; они направляются в файл журнала.
- Широкие Unicode-символы и emoji очищают все занимаемые ячейки и не оставляют
  артефактов при повторной отрисовке. При прокрутке изменившаяся строка
  терминала сначала очищается целиком и только затем атомарно перерисовывается;
  неизменившиеся строки не выводятся повторно.
- Заполняющие пробелы окна не затирают continuation-ячейки широких glyph'ов.
  После Unicode-символа курсор позиционируется явно. Значкам Nerd Fonts
  резервируются две ячейки; Nerd Fonts включены по умолчанию и отключаются
  в меню или `TELEGA_NERD_FONTS=0`.
- Статусная строка не показывает количество загруженных сообщений.
- Все кликабельные элементы имеют точные mouse-hitbox области.
- Архив, Telegram-папки, поиск, меню, вложения и online-статусы остаются
  рабочими после любых изменений UI.
- Прокрутка списка чатов не привязана к открытому собеседнику и не переключает
  саму переписку. Имя и аватар в шапке открывают профиль с данными и отдельными
  вкладками общих медиа, файлов, музыки, голосовых, ссылок и закрепов.
  Вкладки догружаются через серверный поиск, независимо от загруженной ленты;
  устаревшие ответы после смены вкладки/чата игнорируются.
- Закрепы показываются под шапкой чата; клик переходит к сообщению, [list]/`p`
  открывают весь список. Меню сообщения закрепляет/открепляет через Telegram API.
  Переход к старому сообщению загружает контекст и продолжает историю в обе стороны.
- Постоянный кеш медиа содержит только аватарки в `~/.cache/telega/avatars`.
  Сообщения и превью открытого чата живут в памяти, освобождаются при его
  закрытии; полные медиафайлы существуют только на время просмотра. Сессия,
  лог и временный runtime также находятся под `~/.cache/telega`.
  При запуске удаляются runtime-каталоги процессов, которых больше нет.
- Медиа-вьювер сразу показывает уже загруженную миниатюру, пока полная картинка
  догружается; если миниатюры ещё нет, она и полный файл запрашиваются
  параллельно. Видео получает Telegram-чанки по запросу декодера до завершения
  загрузки, показывает таймлайн и имеет управление паузой.
- Контролы полноэкранного видео находятся по центру непосредственно под кадром.
  Только их собственные hitbox-области управляют плеером: клик по кадру не
  перехватывает кнопки, а клик по пустому месту закрывает viewer.
- Таймлайн видео поддерживает клик и drag мышью. При отпускании ползунка
  декодер и звук переходят к выбранному времени, включая незагруженные участки.
  Локальный HTTP Range bridge даёт ffmpeg/mpv произвольный доступ к чанкам
  Telegram; RAM-кеш ограничен 12 МиБ и освобождается при закрытии.
  Индекс MP4 в конце файла загружается отдельным запросом, без полного скачивания.
- Затемнение, медиа и контролы — три отдельных TGP-слоя выше изображений чата.
  Текст и кнопки плеера растеризуются в верхнем слое и не проваливаются под фото.
  Закрытие/перемотка не блокируются на заполненной очереди кадров декодера.
- Каждое голосовое сообщение и музыкальный файл имеют inline-плеер с текущим
  временем и перемоткой. Одновременно играет не более одного аудиосообщения.
- Поле ввода занимает только нижнюю часть правой панели открытого чата; левая
  панель со списком чатов продолжается до нижней границы терминала.
- Скруглённые рамки (`border = 0`) имеют только список чатов и внешняя область
  чата. Сообщения без обводки. Composer расположен внутри общей рамки чата.
- Папки показываются вертикально слева от списка чатов с иконками, названиями,
  исходным порядком Telegram и поддержкой общих папок; на узком экране доступны
  через меню. Настройки тем и иконок открываются через меню приложения.
- Шапка списка чатов не показывает имя telega. Внутренняя ☰ сворачивает список
  до аватарок и разворачивает обратно, освобождая место переписке. Крайняя
  левая ☰ над папками по-прежнему открывает меню; её действие не меняется.
  Прокрутка учитывает текущую ширину; поиск и меню доступны в компактном режиме.
- Пустая/невидимая иконка папки заменяется запасной; стандартные эмодзи папок
  сопоставляются Nerd Fonts, при их отключении используются ASCII-значки.
- Официальные `.tdesktop-theme` (текст и ZIP) / `.tdesktop-palette` и ссылки
  `t.me/addtheme/...` импортируются через `t`. Палитра и прозрачность сохраняются
  в `~/.cache/telega`. Обои из архивов не рисуются в TUI.
- Клик по обычной или скрытой entity-ссылке addtheme открывает предпросмотр,
  не меняя текущую палитру и настройки. Только Apply/Enter сохраняет выбор и
  устанавливает удалённую тему через API; Esc/Cancel отменяет предпросмотр.
- Вложения имеют меню «фото/видео», «файл в исходном качестве», «аудио»,
  файловый браузер с каталогами, прокруткой и отдельной отправкой.
- Ctrl+V / Paste в меню читает локальный системный буфер: изображения, файлы и
  URI-списки; терминальный bracketed paste принимает длинные Unicode-пути и
  многострочный текст как одно событие, никогда не нажимая Send автоматически.
  Перед отправкой файлов есть предпросмотр, выбор сжатого фото или исходного
  файла, Send/Cancel. Исходники не меняются; временные clipboard-файлы удаляются.
  Фото со сжатием преобразуются в JPEG до 2560 px в памяти, файлы идут без
  преобразования. На Linux в Nix closure входят wl-clipboard/xclip.
- Реквизиты приложения могут встраиваться через локальный игнорируемый
  `api-credentials.env` при Cargo/Nix-сборке. Окружение имеет приоритет;
  файлы сессий никогда не встраиваются и не публикуются.
- Custom emoji из `messageEntityCustomEmoji` загружаются через Telegram API и
  рисуются TGP поверх соответствующей позиции entity в строке сообщения.
  Под загруженной картинкой полностью очищаются ячейки текстового fallback,
  включая широкие/ZWJ emoji, с сохранением фона и исходного текста для Copy.
  Без TGP, при загрузке/ошибке текст остаётся. То же правило действует в реакциях.
- Кнопка 🙂 в composer и Ctrl+E открывают меню Emoji/Stickers/Custom. Мышь,
  колесо, стрелки, Enter, Tab и Esc имеют отдельную обработку, без потери
  черновика. Наборы и их превью загружаются в фоне; декодируется только видимая
  сетка, первый кадр передаётся до завершения анимации. Кеш — в RAM текущего чата.
- Без Premium custom emoji не запрещаются локально: обычный emoji + TextUrl
  `tg://emoji?id=DOCUMENT_ID` — совместимый формат, распознаваемый этим клиентом.
  Другие клиенты без поддержки видят обычный emoji со ссылкой; серверный Premium
  не подделывается. Premium/free используют MessageEntityCustomEmoji. Диапазоны
  entity учитывают UTF-16; неудачная загрузка одного ID не сдвигает остальные.
  Custom emoji анимируются inline; графические ID разных сообщений/слотов и
  слоёв не должны совпадать. Смена статичного стикера обновляет TGP по identity.
- MessageEntityPre сохраняет пробелы/табуляцию/пустые строки и всегда рисуется
  на непрозрачном фоне. Указанный язык даёт подпись и синтаксическую подсветку;
  без языка их нет. Небольшая Copy-hitbox копирует полный неизменённый исходник.
  md/markdown рендерится как Markdown: продолжения списков имеют висячие отступы,
  явные переносы сохраняются, в том числе в нумерованных и вложенных списках.
  latex/tex/math — только читаемый текст (греческие буквы, операторы, дроби,
  корни, индексы). Графический рендер полностью отключён независимо от TGP;
  внешний TeX/Python для формул не запускается, Copy сохраняет исходник.
- ПКМ по сообщению открывает Telegram-подобное меню с выбором реакции, ответом,
  копированием через OSC 52, пересылкой в выбранный чат и подтверждаемым
  удалением. Одиночный ЛКМ выбирает сообщение, двойной ЛКМ активирует Reply.
  Удаление имеет отдельную плашку с выбором «у себя» / «у всех»; в каналах/
  супергруппах используется channel API с удалением у всех и проверкой прав.
  Текущие реакции и их счётчики показываются под сообщением.
- Поле ввода сохраняет фокус при отправке и выходит из него по Esc. Shift+Enter
  вставляет перенос, Enter отправляет; composer растёт до пяти видимых строк.
  Esc снимает фокус без удаления черновика/reply; `i` возобновляет ввод.
  terminalib распознаёт CSI-u/modifyOtherKeys, режим клавиатуры восстанавливается.
- Крайняя левая ☰ открывает отдельное непрозрачное скруглённое окно настроек
  поверх чата/профиля и TGP-изображений. Вкладки: Appearance, Media, Folders,
  Storage, Controls. Переключатели autoplay/анимации сохраняются
  в ~/.cache/telega/preferences; импорт темы не меняет черновик сообщения.
- Receiver обновлений SenderPool сохраняется и передаётся в stream_updates
  с catch_up. Входящие сообщения, правки, удаления и реакции приходят в UiEvent;
  исключаются дубликаты, устаревшие peer/thread и разрывы старого контекста.
  При прокрутке история остаётся на месте, при latest следует за сообщениями.
  При выходе состояние updates синхронизируется с сессией.
- Клик по аватару в профиле открывает TGP-галерею profile photos с исходными
  пропорциями, ←/→, Esc/кликом снаружи и ленивой серверной пагинацией.
- Все реакции, включая custom без Premium, отправляются только через нативный
  sendReaction. Не блокировать выбор локально по подписке и никогда не отправлять
  reply вместо реакции. Если сервер требует Premium, показать ошибку в TUI без
  фиктивной успешной реакции и без новых сообщений; не обещать обход проверки.
  Старые carrier-ответы tg://emoji?id=DOC&telega_reaction=MSG только читаются и
  снимаются/мигрируют по явному действию пользователя. Учитывать точный reply_to,
  author/document/peer ID; не удалять чужие carriers и сообщения другого чата.
  Их метаданные остаются в RAM отдельно от пагинации и зависят от загруженной истории.
- Реакции снимаются повторным кликом по своей реакции либо Remove my reactions.
  All reactions загружает разрешённый каталог Telegram, недавние реакции и
  установленные custom emoji-наборы. Лимит собственных реакций берётся из
  appConfig; старые удаляются при превышении лимита. Custom/premium реакции
  рисуются по document ID через TGP с реальным emoji-fallback, не общей звездой.
  Star-реакции отображаются, но действия с оплатой не выполняются.
- Исходящие сообщения имеют ✓ (приняты сервером) / ✓✓ (прочитаны) возле времени.
  read_outbox_max_id обновляется в фоне, без перезагрузки сообщений.
- Ответы показывают над текстом автора и фрагмент оригинала/описание вложения.
  Клик по цитате загружает контекст исходного сообщения, даже вне текущей ленты.
  Превью оригиналов запрашиваются в фоне только для видимых ответов, кешируются
  в памяти текущего чата с учётом peer ID; устаревшие ответы API игнорируются.
- Любое новое пожелание пользователя записывается в `TASKS.md`, выполненные
  изменения отражаются в минимальном `CHANGELOG.md`. Правки и необходимые
  коммиты в terminalib разрешены; чужие несвязанные изменения не включаются.

## Перед завершением изменения

1. `cargo check`
2. `cargo test`
3. `cargo clippy --all-targets -- -D warnings` в Nix dev shell
4. `nix run . -- --help`
5. Обновить минимальный `CHANGELOG.md`.
